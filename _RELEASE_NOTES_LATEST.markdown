#### 4.9.1 版針對 4.9.0 版更新了下述內容：

- 懶人包總結：雙拼敲入不可能開啟任何碼之首鍵時當場示警並丟棄之；雙拼標點等非碼鍵的處理方式亦有調整；對單次擊鍵處理過程中的臨時的空狀態不再套用內文組字區顯示處理；改良了選字窗在螢幕底端時的位置避讓行為。
- 體驗：[所有發行版] 雙拼狂打模式下，尚未配對成碼之首鍵遇到「非碼鍵」（標點、數字、Tab、方向鍵、Enter、空白鍵、刪除鍵）時，現在一律比照全拼拼音之處理方式：先將該首鍵已能開啟之讀音結算進組字區，再落本鍵。
  - 標點即落標點、數字則落為半形數字原文；方向鍵與 Tab 則結算該首鍵、並開出選字窗。
  - 先前該首鍵會被直接丟棄：敲標點、方向鍵、Tab 時，連本鍵也一併交還給客體、組字區就此結束；敲數字時雖仍落一個半形數字，但那枚尚未成碼之首鍵已被吃掉。
  - 非狂打之雙拼不受影響：其「退位作廢」語義仍為「逕行撤銷該首鍵、並把本鍵交還給客體」。
- 體驗：[所有發行版] 雙拼打字模式下，敲入「不可能開啟任何碼之首鍵」時，現在當場以紅色提示告知、並丟棄該鍵——狂打與否皆然。
  - 例如微軟雙拼之 `a`、`e`、`;`：這三鍵只能居次鍵之位，不可能作為首鍵開啟任何雙拼碼。
  - 先前這類首鍵會被默默收下（副駕選字窗因無讀音可列而不出現）；隨後敲數字等鍵時，則只換得「毫無動作、且響一聲蜂鳴」。
- 修正：[所有發行版] 雙拼打字模式下，客體端組字區不再發生「先清空、再重建」的往返：非狂打之「退位作廢」若在同一輪按鍵內旋即又落本鍵，唯音現在會等這一輪分診結束才刷新客體端之組字顯示，而不在中途先清空一次。
  - 這免除了 macOS 26 之後的 Spotlight 等客體白跑一輪停用／啟用例程，亦免除了舊版 Spotlight 殘留組字殘影之情形。
- 修正：[所有發行版] 改良了選字窗在螢幕底端時的位置避讓行為。此前的避讓方法不準確、會遮住浮動組字窗。
- 修正：[所有發行版] 修復了輸入法自身的浮動組字窗與 Mozilla 軟體（FireFox 等）的部分介面的文字輸入框的相容性缺陷。
- 辭典：[所有發行版] 例行語彙資料更新；全字庫資料已跟進至 2026-10-05 版本。
