#### 4.9.0 版針對 4.8.8 版更新了下述內容：

- 懶人包總結：新增雙拼（Dualpin）打字支援；修復了打字學習記憶的兩樁會逐漸影響打字體驗的故障（資料過度累積、殭屍記憶復活等）。
- 修復：[所有發行版] 修復了漸退記憶模組對打字學習資料的記憶量失控的故障：以往打字學習得越久，敲字反應就越遲鈍，直到清空打字學習記憶才瞬間恢復原速。
  - 記憶量上限（500 筆）從未真正生效：自資料檔案重播日誌時，一路重播進來的記憶鍵沒被登記進 LRU 序列，於是永遠不會被挑出來汰除，記憶數只增不減，且一次比一次多。
  - 每次敲字都重新巡視全部記憶並逐鍵解析：敲字耗時與累積的記憶量成正比，於是記憶失控直接變成敲字延遲。
    - 現在為記憶表配上三組索引（依原讀音、依去聲調讀音、依各讀音分段）與解析結果快取，登錄與移除時同步維護，檢索改為定點查表。
    - 新增的容量收斂在三個可能撐破上限的入口一律套用（讀取記憶快照、重播日誌、寫入新記憶），並確保記憶表與 LRU 序列不再彼此不一致；對既有超量資料則以時間戳最舊者優先汰除。
- 修復：[所有發行版] 修復了「被汰除／已淡出的打字學習記憶在下次啟動時復活」的故障。
  - 以往「刪除某某記憶」在日誌內被記成字典裡的「此鍵不存在」，這種寫法無法區分「從未記錄過」與「已被刪除」，於是日誌重播時這些刪除指令全部落空，而快照內已經載入的記憶就此長存。
  - 現在改以有序的變更序列（清空／記錄／刪除）交給載入方，依日誌發生順序套用；清空會作廢其先前之變更、但自身仍被交付，以便亦清空快照內容。
  - 同時移除了「刪除」與「記錄」共用的兩秒節流：節流記錄不會漏掉任何資料（寫日誌時再讀即時記憶表），節流刪除則會把該鍵留在快照或已寫出的日誌內坐等復活。
- 體驗：[所有發行版] 新增雙拼（Dualpin）打字支援，基於唯音輸入法自家的「Arimitsu」雙拼轉譯模組（命名取自漢語拼音發明者 周有光 之姓名）。
  - 雙拼的原理：僅用有序兩碼鎖定唯一存在的漢語拼音讀音（不包括聲調）。
  - 該特性需要在「唯音輸入法偏好設定->鍵盤設定」內手動開啟，開啟之後對拼音打字模式生效。
    - 唯音輸入法的配置助手也支援對雙拼的配置特性，惟雙拼方案仍需手動指定。
  - 出於雙拼方案授權特性差異之疑慮，唯音輸入法同捆的雙拼方案只有微軟雙拼方案與 GB/T 官標雙拼方案。
  - 小鶴雙拼等其餘方案的使用者們有兩種選擇：
    - 利用「唯音輸入法偏好設定->鍵盤設定」頁面的雙拼方案編輯器自行配置。
    - 在唯音輸入法官方網站找到[現成的雙拼方案 JSON 配置檔案](https://vchewing.github.io/Dualpin_Schema.html)。
      - 包含下述方案：智能ABC/拼音加加/搜狗雙拼/紫光華宇/小鶴雙拼/四通雙拼/周志農自然雙拼。
  - 兩鍵若湊不成合法之雙拼碼，唯音會蜂鳴警告、並以紅色提示告知此時敲的雙拼碼不合規，該兩鍵亦會被丟棄、不會落為原文。
  - 雙拼打字模式下，退格鍵以「整個音節（雙拼碼）」為退格粒度（而非逐漢語拼音字母退格）；尚待配對之首鍵則由退格鍵就地撤銷。
  - 426 條漢語拼音詞幹中，孤立 ㄝ（`eh`）於漢語拼音之拼式空間內存在、卻不屬雙拼之鍵位空間（DIPE），故「欸」一類僅此一音之字在雙拼模式下敲不出來，需逕切至全拼輸入或注音輸入。（這類漢字往往可以用「`ai1`」「`ei2`」等替代讀音敲出來。）
  - 雙拼與拼音狂打可以並用：狂打開啟時（此乃預設行為），雙拼之音節讀音續留於組音區，交由狂打之自動套用與重切分處置；雙拼之首鍵尚未成碼，但已顯示於副駕選字窗的頂部、且同時標示該首鍵於其位所代表之聲/介/韻。
- 體驗：[所有發行版] 對「位於游標身後的漢字讀音」成功進行聲調覆寫時，現在會在此時所出現的工具提示文字串的末尾追註「此時已施加的新的聲調」。
  - 本次新增的雙拼打字模式亦支援該聲調覆寫之特性。
- 辭典：[Aqua 紀念版] 修復了同捆原廠辭典版本從 4.8.0 版開始一直落後於主流發行版的故障。
- 辭典：[所有發行版] 例行語彙資料更新。
